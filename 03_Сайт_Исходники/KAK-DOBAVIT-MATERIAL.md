# Как добавить материал

Сайт собран так, чтобы новая статья не требовала правок в навигации,
поиске и подвале. Ниже — три шага и одна проверка.

---

## 1. Создать страницу

Скопируйте `kozha-arkhitektura-kollagen.html` как шаблон: в нём уже есть
шапка, подвал, прогресс чтения, паспорт, содержание и схемы.

Что заменить:

| Что | Где искать |
|---|---|
| Заголовок вкладки | `<title>` |
| Описание для поиска | `<meta name="description">` |
| Адрес страницы | `<link rel="canonical">` |
| Заголовок статьи | `<h1>` и `<div class="chip-row">` |
| Паспорт | блок `<div class="passport">` |
| Содержание | `<nav class="toc">` — ссылки на `#якоря` разделов |
| Основной текст | внутри `<article>` |

Каждый раздел начинается с заголовка с якорем:

```html
<h2 id="kollagen">6. Пять порядков сборки коллагена</h2>
```

`id` должен совпадать с `href="#kollagen"` в содержании.

---

## 2. Дописать в поиск

В `index.html` найдите `window.SITE_SEARCH` и добавьте объект:

```js
{
  "title": "Название статьи",
  "type": "База о коже",          // раздел, к которому относится
  "href": "imya-fajla.html",
  "desc": "Одно предложение о чём это.",
  "keywords": "веки отёк полинуклеотиды деликатные зоны"
}
```

`keywords` — обычная строка через пробел. Именно по ней находятся
запросы, которых нет в заголовке.

Через `run_shell` это делается скриптом `add_search.py`: допишите запись
в список `SEARCH_INDEX` и запустите — форма и скрипт не меняются.

---

## 3. Указать в разделе

Статья должна быть доступна не только по прямой ссылке. Добавьте карточку
на страницу-хаб (`baza-kozhi.html`, `katalog-procedur.html` и т.д.):

```html
<a class="article-card" href="imya-fajla.html">
  <span class="chip chip--science">База о коже</span>
  <h3>Название статьи</h3>
  <p>Короткое описание, одна-две строки.</p>
  <span class="article-card__meta meta">18 минут чтения</span>
</a>
```

Если статья заменяет «материал недели» на главной — обновите блок
`<section>` с комментарием `FEATURED ARTICLE`.

---

## 4. Пересобрать служебное

```bash
python3 build_sitemap.py      # sitemap.xml и robots.txt из реальных файлов
python3 apply_shell.py        # единая шапка и подвал на всех страницах
```

`sitemap` собирается из фактически существующих файлов, поэтому битых
адресов в нём не появляется. Перед публикацией замените домен:

```python
DOMAIN = "https://example.com"   # → ваш домен
```

## Добавить схему

Схемы строятся скриптом `figs/build_figs.py`, а не рисуются руками —
так подписи не разъезжаются и проверяется выход за холст.

Схема — это набор элементов с атрибутами, которые читает `assets/app.js`:

| Атрибут | Что делает | Пример |
|---|---|---|
| `data-at="0.3"` | появление с 30% прогресса | слой проявляется |
| `data-out="0.7,0.9"` | исчезновение между 70% и 90% | ядро клетки бледнеет |
| `data-ty="0,-244"` | перенос по вертикали | клетка поднимается |
| `data-scale="1,1,1.7,0.34"` | деформация (уплощение) | клетка становится плоской |
| `data-draw="1"` | прорисовка обводки | волокно рисуется |
| `data-flow="3"` | бегущий пунктир | кровоток |

Прогресс — одно число от 0 до 1. Поэтому схему можно проиграть,
остановить и проскроллить ползунком вручную.

Валидатор в конце скрипта проверяет, что ни одна подпись не выходит
за пределы холста и не накладывается на другую.

---

## Правила, которые стоит соблюдать

- **Один смысл на одну схему.** Если убрать анимацию и смысл не потерялся —
  анимация лишняя.
- **Палитра фиксирована:** крем, глубокий зелёный, терракота. Никакой
  «медицинской синевы» и глянцевого 3D.
- **Уровень доказательности ставится явно** — плашкой, а не словами
  в тексте:

```html
<span class="ev ev--stable">Устойчиво</span>    консенсус
<span class="ev ev--likely">Вероятно</span>     данные с оговорками
<span class="ev ev--debated">Обсуждается</span> гипотеза
```

- **Не обещать сроков, которых нет.** «Эффект через неделю» для
  коллагена — фактическая ошибка, а не маркетинговое преувеличение.
- **Микрофотографии не «оживлять».** Для SEM допустим только медленный
  Ken Burns, иначе читается как манипуляция.
