Структура сайта

Полная архитектура: 34 страницы в четырёх уровнях вложенности, шесть шаблонов, трёхуровневая система приоритетов запуска. Схема спроектирована так, чтобы каждая статья имела минимум три входящие внутренние ссылки — это критично и для SEO, и для удержания читателя.

P1 — запуск в первую очередь P2 — второй этап P3 — наполнение по мере готовности
Принцип 1

Хаб → кластер

Каждый раздел — хаб-страница с полным списком кластера. Ни одна статья не висит в пустоте.

Принцип 2

Минимум 3 ссылки внутрь

Каждая статья ссылается на 3+ смежных материала по теме, а не на главную.

Принцип 3

Один URL — одна тема

Без дублирующих страниц под разные запросы: конкуренция страниц внутри сайта вредит обеим.

Принцип 4

E-E-A-T на уровне структуры

Автор, редакционная политика и источники — не декор, а отдельные страницы с постоянными ссылками.

Шаблоны

Шесть типов страниц

1 · Section Hub

Заголовок + описание раздела в 2–3 строки, фильтры по уровню сложности, сетка карточек. Никаких длинных текстов — задача распределить, а не убедить.

2 · Article · Long Read

TOC, читательский прогресс, буквица, callout-блоки «Врачебный нюанс» и «Уровень доказательности», таблицы сравнения, SVG-схемы, блок источников.

3 · Procedure Card

Верхний блок — «паспорт» из 4–6 ячеек в моно-шрифте: реабилитация, дискомфорт, срок эффекта, число сеансов. Дальше механизм, показания, ограничения, альтернативы.

4 · Catalog + Filter

Фильтр по четырём осям, компактные карточки в 3 колонки, счётчик результатов. Реализуется на чистом CSS/JS или Alpine — без тяжёлого фреймворка.

5 · Author / Editorial

Фото, квалификация, принципы оценки доказательности. Один раз написан — используется как постоянный блок в каждой статье.

6 · Reference Library

Пронумерованный список источников с якорями вида #ref-03. Статьи ссылаются на конкретный якорь, а не дублируют библиографию.

Техническая реализация

Стек и требования

АспектРешение
Генератор Astro — статический вывод, нулевой JS по умолчанию, компоненты для повторяющихся блоков (паспорт процедуры, callout, карточка). Альтернатива проще: Eleventy. Не WordPress: 34 страницы не требуют CMS, а статика даёт скорость и безопасность.
Контент Markdown/MDX в репозитории + frontmatter: title, description, section, priority, evidenceLevel, updated, sources[]. Это позволяет автоматически собирать хабы и sitemap.
Стили Один CSS-файл с custom properties (уже собран: assets/moxie.css). Никакого Tailwind — дизайн-система маленькая и стабильная, utility-классы только усложнят.
Шрифты Cormorant Garamond (600 + italic), DM Sans (400/500/600), JetBrains Mono (400/500). Self-host в WOFF2, font-display: swap, preload для двух основных начертаний.
Изображения AVIF + WebP, srcset, loading="lazy" кроме первого экрана. Схемы — инлайновый SVG (масштабируется, доступен для скринридеров, весит 3–8 КБ против 200 КБ PNG).
Доступность Контраст ≥ 4.5:1 для текста (палитра проверена), aria-labelledby на всех схемах, prefers-reduced-motion для всех анимаций, полная работоспособность с клавиатуры.
SEO Schema.org: MedicalWebPage для статей, Person для автора, MedicalProcedure для карточек, BreadcrumbList везде. Canonical, OG-теги, sitemap.xml, robots.txt.
Хостинг Netlify / Cloudflare Pages / GitHub Pages — любой статический хостинг. Деплой по push в main. Стоимость: 0–5 $/мес на старте.

Критично для запуска

Не начинайте с каталога процедур. Сайт без фундаментальной базы о коже превращается в ещё один список методик — а таких сотни. Ваше преимущество именно в том, что вы объясняете механизм до того, как продаёте процедуру. Волна 1 задаёт этот тон, и её нельзя пропускать.
